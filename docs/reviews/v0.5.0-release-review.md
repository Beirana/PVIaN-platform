# v0.5.0 发布前双独立审查与主复核

审查日期：2026-07-31。范围为 v0.4.0rc1 之上的 gateway client Bearer、public alias facade、
离线保真合同和交付文档。两份独立审查均为只读、未读取 `.env`、未联网。

主控第二轮复核以 `PVI_NETWORK_DISABLED=1` 运行全量离线验收：69 passed、1 条第三方 Starlette
TestClient 弃用 warning；Ruff、数据、OpenAPI、matrix 与敏感/出站扫描均通过。

随后发现状态文件仅有进程内锁这一发布级 P1：网关与外部 qualifier 可互相覆盖同一 JSON。已修复为相邻
lock 文件的 Windows/POSIX 跨进程互斥、所有读/读改写均受保护、原子 replace 保留；qualification 合并
并发发生的运行计数/失败状态。新增 spawn 多进程 success/failure 与 qualification 竞争测试、写失败恢复
测试；随后已在最终 tag 前重新执行完整离线验收。

## 独立安全/鉴权审查

- 发现 P0：若 `revoked` 与 `active` 条目意外配置同一 secret，旧实现在条目顺序特定时可能把吊销 key
  识别为 active。已修复为启动时拒绝任何已注入的重复 digest，并令运行时匹配采用 revoked 优先。
- 建议的密钥强度、泄漏 sentinel、就绪条件和反向代理日志治理均已落实：key 至少 32 UTF-8 bytes；
  synthetic client/provider sentinel 不出现在响应、route/capability、状态文件或认证对象表示；反代样例
  使用不含 Authorization/body 的专用日志格式。
- 复核：missing/invalid/revoked 仍在 body/route/forwarder 之前返回 401/401/403，零上游调用。

## 独立协议/保真审查

- 发现 P0：旧 `/v1/models` 只看资格 state，未预检当前 profile/endpoint/credential，可能列出随后会本地
  失败的 alias。已修复为列表与两种调用路径均解析 profile、endpoint、base URL 和 provider credential；
  漂移/缺凭据在本地 409 拒绝，不计为 transport failure。
- 增加 direct / explicit-route / alias 三路字段级差分，覆盖 messages、thinking、tools、assistant/tool
  replay、reported model、usage 与请求 ID；并补 alias gzip、SSE reasoning/usage/`[DONE]`、429、503 与
  OpenAI SDK `models.list()`。
- 复核：无自动 fallback、重试或供应商替换；alias 只改写顶层 `model`，explicit route 保留请求字节透明。

## 最小真实 smoke

同日以临时本机网关和仅进程内 gateway Bearer，对当前 callable 的
`pvian/bailian-cn-beijing/deepseek-v4-pro` 发起 1 次 non-stream thinking 请求。结果为 HTTP 200；
reported model 为 `deepseek-v4-pro`，reasoning 字段与 usage 均出现，response route 为
`bailian-cn-beijing:deepseek-v4-pro`。网关随后停止。没有保存 key、prompt、response、thinking 或远端
错误正文。该单样本仅是当前时间窗的接入观察，不构成 SLA 或长期稳定性结论。
