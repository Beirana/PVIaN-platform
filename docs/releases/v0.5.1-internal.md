# PVIaN 0.5.1 内部版发布说明

发布日期：2026-07-31。

## 本版内容

v0.5.1 是建立在 v0.5.0 运行时冻结点之上的规划与文档整理版本。它新增两份当前权威入口：

- [`../../PROJECT_STRUCTURE.md`](../../PROJECT_STRUCTURE.md)：当前结构、边界、调用流、thinking 合同和
  provider 接入路径；
- [`../../ROADMAP.md`](../../ROADMAP.md)：0.5.x 迭代策略、能力表积累与协议方言收敛路线。

README 已缩减为快速入口；被替代的设计、计划、迁移登记和阶段性审核保留在
[`../archive/INDEX.md`](../archive/INDEX.md)，并明确标记为历史背景而非当前合同。

## 新增规划

未来的 provider/model 能力表会将稳定绑定身份与观测元数据分开。稳定身份包括 endpoint operator/provider、
声明的上游来源、region/base URL policy、endpoint/path/transport、profile ID/version、
requested model、model revision/deployment、相关配置摘要、API surface/version 和请求方言版本；
reported model、观测时间、runner revision 和 evidence/config digest 单独记录。中转网关运营方与其声明的上游来源不会合并，
也不会按模型名称复制能力。表单计划覆盖：

- thinking/reasoning 的请求参数、非流式字段、SSE event/delta 字段和 token 摘要；
- tool schema、tool choice、native/text-simulated/provider-built-in 表示、provider 或 consumer/external
  runtime 的执行责任、并行/流式 tool call、call ID、assistant replay 与 tool-result replay；
- OpenAI Chat Completions、Responses API 及未来单独批准的其他 Messages/Events surface；
- usage、finish reason、请求 ID、gzip/SSE 和分类错误/短窗稳定性。

能力结论继续区分 `advertised / observed / effective`，并与 qualification TTL/漂移等 operational
callability、消费者 requirements 分层。0.5.x 先积累可追溯表单和脱敏证据；只有覆盖多个真实
provider/model/API surface 并经实验平台稳定使用后，才考虑可逆、可追溯的薄 adapter 或 0.6 合同。

## 验证

发布前在 `PVI_NETWORK_DISABLED=1` 下完成全量离线复核：Ruff 通过，pytest `69 passed`
（另有 1 条第三方弃用 warning），数据、冻结 OpenAPI、Yunwu 4×3 matrix、敏感内容与未经授权出站扫描通过。
本版没有发起 provider 请求，也没有读取或保存密钥及原始上游内容。

## 运行时与边界

本版本不修改 v0.5.0 的网关业务逻辑、provider profile、alias、资格状态、鉴权或消费者 API。v0.5.0 的
验证证据与限制仍以 [`v0.5.0-internal.md`](v0.5.0-internal.md) 和
[`../reviews/v0.5.0-release-review.md`](../reviews/v0.5.0-release-review.md) 为准。

仍不包含公网多租户、自动路由/fallback、计费/配额、SLA、验收 B Runtime 或跨 provider reasoning 文本统一。
