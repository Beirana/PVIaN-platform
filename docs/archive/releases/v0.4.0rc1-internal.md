## 可用于内测的范围

- 独立的透明聚合网关进程：仅转发已资格认证的 OpenAI-compatible route；
- Yunwu 与阿里云百炼第一批 profile，使用精确 provider、host、base path、transport 与模型 ID；
- 资格验证可记录目录发现、普通消息、SSE、thinking/reasoning、原生 tool call、assistant replay 与
  tool-result replay 的脱敏观察；
- 网关发现、显式 route 门、模型/route 一致性校验、24 小时有效期和连续五次分类失败的提前复核；
- 普通 httpx 默认压缩协商下的非流式 JSON 与 SSE 转发；网关固定向上游请求 `Accept-Encoding: identity`；
- 受控真实接入验证与短 burst 观察。详细结果见
  [`../../reviews/gateway-short-burst-2026-07-31.md`](../../reviews/gateway-short-burst-2026-07-31.md)。

冻结前离线复核结果：`ruff check`、`pytest`（47 passed）和禁止字段/出站边界扫描均通过。

## 已知边界（不可作为完成项宣称）

- 网关无下游 client API Key/Bearer 鉴权，也无 public model alias；只能部署在本机或受控内网。
- 下游当前必须显式传入 `X-PVIAN-Route-ID` 与精确 upstream model ID；不能只填裸 model 名。
- 不实现自动选路、健康度替换、重试、fallback、负载均衡、费用策略或工具执行。
- 资格与 burst 结果是时间窗观察，不构成供应商身份、长期能力、稳定性或 SLA 结论。
- 当前真实短窗建议由人工显式选择百炼 route；Yunwu 发生过真实 429，保留为显式备用/对照。
- PVI 验收 B Turn/SSE Runtime、真实 `misalignment-platform` 接入和网关下游统一消费者合同仍未完成。

## 内测使用规则

1. provider API Key 仅由网关进程使用，严禁提交、打印、复制给下游项目或写入 profile。
2. 下游先读取 `/v1/gateway/routes`，仅调用 `enabled` 且未到期的 route。
3. 每日由外部 scheduler 运行 `pvi-probe qualify --due --allow-network --confirm-cost`；CI、网关启动和
   普通调用均不得触发网络资格验证。
4. 出现一次 429、5xx、timeout 或 transport error 时只记录观测，不能据此断言模型不支持；连续五次
   分类失败才使 route 提前复核到期。
5. 生产/跨网络部署前，必须先实现下游鉴权、public alias、TLS/反向代理与访问日志脱敏，并另行审核。
